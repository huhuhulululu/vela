# iOS 三窗计划

> 状态：计划 v1（2026-11-18）。用户裁决：最多 3 路；iOS 先做，macOS 维持单窗，安卓在其双窗里程碑后按 3 路版本移植。依赖：`fix/dual-recent-skip`（双窗共享「最近划走」记录）合入 main 之后开工。

## 冻结区块（需求边界与验收，批准后不可自改）

**需求边界**
- 竖屏可选 1、2、3 路，上下等高叠放，每格 `.resizeAspect` 不裁切、模糊缩略图垫底。横屏一律单窗（与双窗现行规则一致）。
- 设置项由「双窗」开关改为「1 / 2 / 3 路」选择，默认 1，记住选择；旧的 `phoneDual=true` 迁移为 2。
- 只有焦点路出声；焦点切换按现有 `AudioFocusController` 顺序执行，不出现两路同时出声。
- 任一时刻各路房间两两不同；共享「最近划走」记录对 3 路同样生效。
- 画质：2 路维持「两路最高档」；3 路按每格显示尺寸选档（`LaneQuality` 的 displaySize 规则）；热降档与回升对每路生效。
- 画中画只给焦点路；进入时释放其余各路，退出恢复；3 秒未进入则全停。
- 无画中画时进后台全停、网络归零；回前台各路按 §3.2 恢复。
- 减少路数或转横屏：只保留焦点路，其余释放；恢复竖屏与原路数后用 `requestPlay(lane:)` 恢复。
- macOS 行为不变。

**验收标准**
- T-1：`swift test` 全绿；VelaPhoneTests 全绿且数量不少于合入前基线。
- T-2：模型层测试覆盖：3 路两两不重复的全部既有场景（屏蔽、取消收藏、搜索装入与退出、切来源、列表只剩 1 到 3 个、空列表续页恢复、reveal 目标在另一路）；焦点路操作只作用于焦点路；路数增减与横竖屏切换的释放与恢复；`phoneDual` 迁移。
- T-3：iPhone 与 iPad 模拟器 3 路静音实跑（固定测试流）：三格首帧、`lane-rooms` 两两不同、`display-check` 全部 `uncropped=true`、回桌面无画中画时 5 秒内服务端字节为 0、iPad 画中画只剩焦点路联网。
- T-4：G-mac 三轮中位数合格，空闲合格（共享代码改动）。
- T-5：CI 五项全绿；双路审计与盲审无未处理的 high。

## 设计要点

- `LaneID` 新增 `.tertiary`，提供 `allCases` 与按路数取前 N 个的 `active(count:)`；不改 `.primary`、`.secondary` 名字（现有约 700 处引用保持可读）。
- `LaneSelection`：凡「另一路」改为「其他各路集合」；`moved`、`filtered`、`merged`、`revealed`、`replacement`、`refill` 都以「其他各路当前房间 ∪ 最近划走」为排除集；替补顺序固定为 primary → secondary → tertiary，保证确定性。
- `StageModel+Lanes`：路数状态取代布尔双窗；增减路数时按顺序创建或释放 `PlaybackLane`；焦点不可落在已释放的路上。
- 视图：`PhoneDualStage` 泛化为 N 格等高；格间距与现双窗一致。
- 画质：3 路时每路按格子显示尺寸选档；不新增定时器。
- 画中画控制器仍只挂焦点路一个（ADR-007 结论不变）。

## 修订 v2（对抗审查 12 条的裁决，优先于上文；冻结区块随之更新）

**H1 减少路数与临时释放**
- 区分三层状态：用户选择的路数 `laneCount`（持久化）、逻辑路（游标、方向、停留、播放代次）、当前允许播放的路。
- 用户主动减少路数：保留焦点路，再按 P→S→T 顺序补足其余保留名额（跳过焦点）；被移除的逻辑路结算停留（结束原因为布局变更，不记弱落空）后丢弃，不保留恢复状态。保留下来的路若身份需要压紧（例如 P、T 保留、S 移除），把 T 的状态整体迁到 S，焦点随迁，迁移在一次提交内完成，先切声音再迁房间。
- 横屏与画中画是临时释放：只释放播放资源，逻辑路状态全部保留；回到竖屏或退出画中画后按原路数原状恢复。
- 覆盖 3→2、3→1、2→1 在每种焦点位置下的测试，并测「临时释放期间用户改路数」。

**H2 选档三层上限**
- 尺寸上限 `sizeCap`：按格子显示像素选不超过它的最高档；1、2 路时 `sizeCap = 不限`（维持用户裁决），3 路时按格子尺寸生效。
- 热上限 `thermalCap`：serious 降一档，critical 降两档，以当前上限为基准逐档下降；已是最低档则保持最低档。
- 最终上限 = min(sizeCap, thermalCap)；回升到 sizeCap（不是不限）；连续 fair/nominal 满 60 秒才回升，期间再次发热重新计时。
- 触发换档的事件：路数变化、旋转、画中画进出、格子尺寸变化、解析期间上限变化、热状态变化；不新增定时器（回升用一次性任务）。

**H3 解码资源不足**
- 焦点路受保护；`decoderTemporarilyUnavailable` 等资源类错误在非焦点路上按 T→S 顺序降级：该路释放播放项、显示「资源不足」占位，不计入房间失败与重试预算。
- 恢复入口：焦点切到该路时、路数减少时、或 60 秒一次性检查时重试一次。
- 损坏码流仍判房间失败，资源不足与损坏码流的分类边界用样本测试锁住。
- 结论边界：模拟器使用宿主机解码，不能证明 iPhone 三路硬解能力；本阶段只验模拟器与降级路径，真机三路持续播放由用户在 TestFlight 上确认。

**M4 排除集按意图区分**：新分配时其他路当前房间是硬约束；最近划走只约束「向前划」与自动补位；搜索、收藏面板、reveal 直达不受最近划走约束；reveal 命中其他路正在播的房间时只切焦点。候选耗尽时先放宽最近划走，再维持原地，永不同房。

**M5 联合分配**：一次分配内维护动态占用集合（已分配结果立即加入），先处理显式目标与焦点路，再按 P→S→T 替补，最后统一提交；候选 0/1/2/3 个时焦点路优先保留，空格留给非焦点路。测试断言具体落点、方向、焦点与未受影响路的代次。

**M6 两套路身份**：R1 同时扩展 `LaneID` 与 `PlaybackLaneRole` 及其映射、日志标签；采用兼容接口，保证 R1、R2、R3 每一步都能编译且对应测试全绿。

**M7 画中画矩阵**：分别以 P、S、T 为焦点进入，验证其余两路播放项、中继源、在途任务全部释放；starting/active 期间禁止切焦点与改路数；覆盖失败、卡在 starting、超时、迟到回调、后台关闭、回 App 恢复、与横屏叠加。

**M8 出声验收**：增加三路全部有向焦点转换（P↔S、S↔T、T↔P）的有序驱动测试；新路加入、减路数、播放项重建时只有焦点可出声；会话失败时全部静音且不写偏好。实跑仍全程静音，出声正确性由单元测试证明。

**M9 迁移**：新键 `laneCount` 存在且合法（1 到 3）就用它；仅新键不存在时读旧键 `phoneDual`（true→2，false→1），迁移结果立即落盘；非法值按 1；临时单路不覆盖用户选择。覆盖全新安装、旧 false、旧 true、新旧并存、非法值。

**M10 停留结算**：继承非焦点 0.5 权重；三路原始秒、加权秒、焦点秒、来源归属进测试；减路数用布局变更结束原因；每路只结算一次；热门关联与收藏提示只跟焦点。

**M11 实跑工具先行**：R3 实跑前先扩展固定流入口为三个房间、三路唯一标签、探针期望路数、分析器识别 tertiary 与三者去重、画中画源计数，并加负样本（缺第三路日志、第三路重复、后台仍留源都必须判失败）；测试流改为多档，以验证按尺寸选档真的降低了下行。T-1 基线绑定依赖合入后的具体提交。

**M12 可用尺寸**：iPhone 竖屏三格按 `(H − 2×间距) / 3` 计算，验收记录每格点尺寸与画面尺寸；格子高度小于 160pt 的机型（例如 SE 尺寸）最多开 2 路，选择器里第三路置灰并说明原因。
